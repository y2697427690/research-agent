# 科研小助手 Agent — 需求原文（从 科研小助手Agent-AI大模型.pdf 提取整理）

> 本文件由 PDF 正文抽取得到，个别上/下标字符（如 β1、β2 的下标）在原文中为独立小字号字形，
> 抽取时可能缺失；其余文字与原版一致。

## 1. 产品功能

### 1.1 PDF 文件管理和解析

基本的 CRUD 操作，如可以上传 PDF 格式的论文，包括批量上传。上传之后需要对 PDF 进行解析，
把文字提取出来，此外也可以考虑更高级的文档解析，如识别文档的结构，识别公式、表格、图表等。
下面是一些功能的详细说明。

#### 1.1.1 PDF 文件内容去重

Agent 需要根据内容去重（文件不同，但是内容完全或者基本相同），可以用于测试的文件是：
1706.03762v1.pdf 与 1706.03762v7.pdf，这两个文件是论文《Attention Is All You Need》在 arXiv 上
发布的第一版与第七版。如果存在重复的论文，可以提示用户选择保留哪个版本，如果不能，Agent 可以
提示用户保留新的版本。

#### 1.1.2 PDF 文件解析

对上传的 PDF 论文进行解析，PDF 文件可能是扫描的图片，比如 1706.03762v1_img.pdf，也可能是
很长的数据，比如书籍 Understanding Deep Learning
(UnderstandingDeepLearning_02_09_26_C.pdf)。解析的粒度越细越好。下面是一些细粒度解析的参考：

- 标题
- 作者（包括顺序、联系方式 / 工作单位等等）
- 摘要
- 一级标题（如 Introduction、Background、Experiment 等等）
- 二级标题 / 三级标题
- 表格
- 图表（chart）
- 公式
- 参考文献
- 附录

### 1.2 知识问答

#### 1.2.1 针对单篇论文的问答

通过 RAG 或者其它技术，实现问答。如果可能，给出参考的原文，从而让用户能够发现模型的幻觉。
下面是一些例子：

1. 论文 Attention Is All You Need 的第 6 作者是谁，在哪个公司 / 机构工作？
2. 其中 Adam 优化器的超参数 β1 与 β2 分别被设置为了多少？（接上文省略了论文文字）
3. 这篇论文中提到的 Transformer 架构，在训练 Base 模型时使用了多少个 GPU？具体是什么型号？
4. Transformer (big) 模型在 English-to-German 任务上的 BLEU 分数是多少？当时的 State-of-the-art
   模型是多少？提升了多少？
5. 请列出论文中引用的关于 "Layer Normalization" 的参考文献（References）的完整作者与年份。

#### 1.2.2 针对多篇论文的问答

1. 根据《Attention Is All You Need》与《BERT: Pre-training of Deep Bidirectional Transformers
   for Language Understanding》。请对比：BERT 的架构与原始 Transformer 的 Encoder 有什么
   承袭关系？BERT 丢弃了原始 Transformer 的哪个部分？
2. 对比 GPT-1、GPT-2 与 GPT-3 的论文，说明这些模型的参数的演化。
3. GPT-2 相比于 GPT-1，在 Transformer 的 Layer Normalization（LN）位置上做了什么关键的调整？
4. 从 GPT-1 到 GPT-3，模型的最大上下文 Token 长度（Context Window）分别递增到了多少？

### 1.3 阅读和翻译

我们希望可以在科研小助手这个平台进行论文阅读，此外为了提升阅读速度，希望能够对论文进行翻译。

#### 1.3.1 基本阅读功能

- 要考虑原文的排版（双栏 / 单栏），公式、表格的排版。

#### 1.3.2 智能引导与快读速览

1. 把一级标题、二级标题做成树状导航栏，快速定位到某个部分（比如论文《Attention Is All You
   Need》可以快速跳转 3.2.2 Multi-Head Attention）。
2. 对于文章引用的参考文献，比如 "We employ a residual connection [11] around each of the
   two sub-layers, followed by layer normalization [1]"，可以点击快速跳转到 References 的 "[1]
   Jimmy Lei Ba, Jamie Ryan Kiros, and Geoffrey E Hinton. Layer normalization. arXiv preprint
   arXiv:1607.06450, 2016." 并且还可以从 References 快速跳回到原来的位置。

#### 1.3.3 翻译（英到中）

##### 1.3.3.1 部分翻译

翻译论文的某一部分，比如摘要。或者用户选中某一段进行翻译，甚至鼠标划词或者悬停翻译。

##### 1.3.3.2 翻译整篇论文（整个 PDF）

需要考虑：

a. 翻译质量
b. 输出可读性
   一种方案可能是输出 Markdown 或者 Html 格式，在网页重新排版；另外一种方案是输出 PDF，
   重新在原来的位置排版，这要考虑中文英文长度不同带来的问题。
c. 代码、公式保留英文不翻译

##### 1.3.3.3 中英对比阅读

整篇翻译可以实现对比阅读，拖动英文部分，中文部分自动滚动到对应的位置；反之拖动中文，英文
也自动滚动到对应位置。

### 1.4 论文自动下载和推荐

#### 1.4.1 基本下载

1. 给定论文名称，利用搜索引擎等工具自动下载论文并入库。
2. 根据论文的参考文献，自动下载所有（或者文章提到的）参考文献，更高级的可以根据文章内容筛选
   最重要的参考文献，把那些为了引用而引用的去掉。

#### 1.4.2 下载最新论文

定期刷新 arXiv（可以参考 https://info.arxiv.org/help/oa/index.html，使用 sickle 等 python 库），
找到与库里论文相关的新论文（比如大量引用了库里的论文，或者主题非常相关）。

#### 1.4.3 每日 / 每周新论文推荐

根据上一步得到的新论文，进行论文推荐。需要考虑：

1. 新论文与用户兴趣（库里已有的论文）的相关性，最好能根据论文的内容给出推荐理由，比如：这篇
   论文在 xxx 的基础上提出了一种新的 xxx 方法，在 xxxx 数据集上的效果提升非常明显。
2. 是否包含 GitHub 代码，有代码的文章容易复现，优先推荐。
3. 可以考虑加入用户反馈，比如点击，或者可以实现"点赞""踩一下"的功能。
4. 如果 Agent 实现了多用户，可以考虑更复杂的推荐算法，如协同过滤。

### 1.5 论文分析与生成

1. 局域图谱生成：当用户一次性上传一个方向的 20 篇 PDF 文献时，Agent 能够自动解析它们之间的
   引用与被引用关系，并在前端展示它们的引用关系。
2. 核心节点挖掘：利用图论算法，分析这 20 篇 PDF 的内部引用网络，精准算出哪一篇是该领域的"基
   石论文"，哪几篇是"边缘衍生论文"。
3. 自动综述：根据上面的结果，大模型自动生成这个领域简短的综述。
4. 未来工作探索：根据多篇论文的 Future Work 部分，Agent 提出一些下一步值得继续探索的方向，
   要考虑论文的时间以及最新的工作，不要提出已经被最新论文尝试过的 idea。

### 1.6 写作助手

1. 论文框架生成：给定一个 idea，让论文自动生成论文的框架，包括：Abstract、Introduction、
   Related Work、References 部分。确保 References 是真实没有幻觉。
2. 论文架构拓扑图生成：让 Agent 可以根据论文逻辑，直接生成高质量的 TikZ（LaTeX 绘图代码）、
   Graphviz (DOT) 或 Mermaid / Python Matplotlib 绘图脚本。
3. 数据可视化：实验的数据需要做成精美的表格或者图表，用户上传实验产出的原始 CSV 数据，
   Agent 自动将其转化为表格、折线图、柱状图或三维雷达图等。同时，自动为该图生成符合学术
   规范的 Figure Caption（图注说明），不仅说明图表内容，还自动提炼图中的核心趋势结论。
4. 翻译：自动将中文论文的摘要或者全文翻译成英文。

## 2. 测试数据

pdf 目录下包含以下测试用的论文。其中：

1. PDF 文件内容去重：用户先上传 1706.03762v7.pdf，这是一篇新的论文；用户接着上传
   1706.03762v1.pdf，Agent 应该能检测库里存在相同的论文，让用户选择覆盖库里已有的版本还是
   保留库里的版本。如果能，提示用户库里版本比新上传的更新，建议保留库里版本，甚至可以对
   比两个版本有哪些差异。
2. PDF 文件解析：需要能够解析标准的 PDF 论文（比如 1706.03762v1.pdf），也能够解析图片扫描的
   PDF 论文（比如 1706.03762v1_img.pdf），也能解析很长的书籍（比如
   UnderstandingDeepLearning_02_09_26_C.pdf，总共 541 页）。
3. 其它 pdf 无特殊之处，可以用于测试。
4. 参赛者也可以加入更多 pdf 论文以便演示。

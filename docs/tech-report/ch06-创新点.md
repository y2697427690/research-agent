# 第 6 章 创新点说明

## 6.1 判定标准

我们不把"用了某个模型或框架"算作创新。本章只收三类东西：

1. **常规做法有明确缺陷，我们换了做法**——且能说清代价；
2. **可以指出对应的代码位置**——不是文档里的形容词；
3. **有实测数据支撑**——不是"感觉更好"。

## 6.2 技术创新

| # | 创新点 | 常规做法 | 本项目做法 | 代价 / 局限 |
|---|---|---|---|---|
| 1 | **关键词检索的 IDF 信息量闸门** | 两路检索结果直接融合 | 若 BM25 前 5 条命中词的相对 IDF < 0.5，判定为"只命中高频词"，跳过该路 | 阈值是经验值（0.5），换语料需重标定 |
| 2 | **降级链的闭环设计** | 任一路失败则整体报错，或静默降级 | 向量不可用 → 回退关键词结果，并把"置信度较低"写进响应 | 回退结果质量低于混合检索，需前端提示 |
| 3 | **服务端引用治理三件套** | 信任模型输出的 `[n]` | 编号越界即丢弃并告警；假拒答剥离；零引用时追加一次强制作答重试 | 重试会让真正无关的问题多花一次调用（约 1~2 秒） |
| 4 | **结构化片段注入** | 纯语义 Top-K | 命中论文的首页块（作者/机构）与参考文献块按需补入 | 上下文变长，token 成本上升约 20% |
| 5 | **在库内诱导子图上算 PageRank** | 对全图计算中心性 | 只在"库内论文 + 其引用关系"构成的子图上迭代 | 与全图排序结果不同，跨库比较不可直接迁移 |

**证据位置**：

| 创新点 | 代码 |
|---|---|
| 1 | `services/retrieval.py` → IDF 校验段；`MIN_INFORMATIVE_IDF_RATIO` |
| 2 | `services/retrieval.py` → `bm25_fallback` 回退段 |
| 3 | `services/rag.py` → `split_marks` / `drop_false_refusal` / 拒答重试段 |
| 4 | `services/rag.py` → `merge_with_front_matter` / `_maybe_add_references` |
| 5 | `services/graph_service.py` → 幂迭代 PageRank（α=0.85） |

## 6.3 功能创新

| # | 创新点 | 说明 |
|---|---|---|
| 1 | **去重判定顺序影响结论** | 把"扫描件特征"排在"版本号比较"之前：库里已有 v1，再传 `v1_img` 扫描件，若先比版本会得到"无法区分"，丢掉"这是扫描件"的关键信息 |
| 2 | **推荐按钮随新旧翻转** | 文库版本更新 → 主按钮是"保留文库版本"；本次上传更新 → 主按钮变成"用新文件覆盖"。原实现无论哪种情况都推荐保留文库 |
| 3 | **arXiv 检索的零成本精度提升** | 多词自动加引号按短语匹配：`all:"layer normalization"` 第一条即目标论文，而 `all:layer normalization` 会混入大量物理论文；零结果再等满限速间隔重试一次 |
| 4 | **块级翻译缓存** | 整篇翻译 57 次调用，块级缓存让"改一段再读全文"只重译改动段，失败也可按块重试 |
| 5 | **拒绝编造的可比信息** | 旧版重复弹窗展示"新增某附录""参考文献由 34 增至 40 条"——全是写死文本。现只展示上传瞬间能确定的元信息（版本号/大小/页数/解析状态），并明说"逐段 diff 未实现" |

## 6.4 交互创新

| # | 设计 | 为什么算创新 |
|---|---|---|
| 1 | **引用即证据**：回答中的 `[n]` 可展开对应原文片段 | 大多数 RAG 产品只给"参考来源"列表，用户仍需自己找；这里把证据放在结论旁边 |
| 2 | **降级可见**：检索降级时在响应的 `degraded_reason` 里说明原因 | 多数系统静默降级，用户以为拿到了正常结果；这里让"质量下降"变成可见信息 |
| 3 | **未实现能力如实标注**：页面底部写明尚未实现的能力 | 演示类项目常见做法是留假入口；这里选择标注边界（第 2 章 2.4 有完整清单） |

## 6.5 与常见做法的差别

常见 RAG 演示项目的形态是：单一向量检索 + 来源列表 + 不拒答 + 请求时现算索引 + 演示数据。本项目的差别集中在五处——混合检索带信息量闸门与降级链、引用编号强制并要求服务端校验、拒答按三层机制加二元判定、索引内存常驻、界面只展示可追溯的数字。

**一句话总结**：本项目的创新不在"用了更大的模型"，而在**把模型的不可靠性当成工程问题来处理**——用闸门、校验、降级与如实标注，把"可能编造"的系统改造成"编造会被发现并拦截"的系统。

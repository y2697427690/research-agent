# 第 4 章 AI 技术方案

## 4.1 模型选型与关键参数

| 用途 | 选型 | 关键参数 | 为什么选它 |
|---|---|---|---|
| 对话生成 | DeepSeek `deepseek-chat` | `temperature = 0`，超时 60 s | 中文技术问答表现稳定、价格低（约为同级别模型的 1/10），且提供 OpenAI 兼容接口，便于替换 |
| 向量嵌入 | 阿里云百炼 `text-embedding-v1` | 1536 维，批量 10 条/请求，超时 30 s | 中英双语对齐好（本项目大量"中文提问英文论文"场景），有免费额度 |
| 关键词检索 | 自实现 BM25 | `k1 = 1.5`，`b = 0.75` | 参数取文献通用默认值，不调参；中文按 2-gram 切分 |
| 融合 | RRF | `k = 60` | 只用排名不用分数，两路分数量纲不同也能稳定融合 |
| 分块 | 句子级贪心装箱 | 目标 700 字符，重叠 120 字符 | 700 字符约等于一个自然段，既能独立成义，又不至于把结论与条件切开 |

**`temperature = 0` 的理由**：问答要的是**可复现**而不是多样性。同一问题、同一次检索，两次运行应给出同一答案；否则演示与验收结果无法复现。

## 4.2 提示词设计

单篇模式系统提示 **10 条规则**，按职责分四组；检测到 ≥2 篇时换成 **7 条**的对比提示词（对比模式把"回答结构"换成"分述/相同点/差异点/继承关系"）；拒答重试时再追加 1 条强制作答指令。

| 组 | 规则要点 | 解决什么 |
|---|---|---|
| **依据** | 只依据给定片段作答；每个结论必须带 `[n]`；不得虚构编号 | 让引用成为"可验证的义务"而非装饰 |
| **拒答** | 资料无相关内容时明确拒答；只有间接信息时须说明限定条件后作答 | 区分"真答不了"与"只能部分回答" |
| **格式** | 分点或分段作答；代码与公式保留原文；不重复问题 | 保证可读性与可核验性 |
| **对比** | 检测到 ≥2 篇时切换对比提示词，输出「分述 / 相同点 / 差异点 / 继承关系」 | 多篇问答需要结构化输出，而非流水账 |

**踩过的坑**：提示词里写了"能答就直接答，不要先写没有相关内容再补充"，但模型对"论文只给整体配置、未按子模型分列"这类情况仍会先拒答再解释。实测回答是「提供的资料中没有相关内容。资料中仅给出整体训练配置为 eight P100 GPUs [12]」——内容正确，但开头那句会让人误判。

**结论：关键行为不能只靠提示词。** 我们补了两层确定性处理：

1. **剥离假拒答**：若回答带了合法引用，却以"没有相关内容"开头，服务端删除该句（正则匹配，仅在 `citation_count > 0` 时生效）；
2. **拒答重试**：若第一次回答零引用，追加一次更明确的指令重试（"只要资料出现任何相关数字或表述就必须作答，并说明限定条件"），有引用则不触发，正常问题零开销。

## 4.3 抗幻觉三层机制

| 层 | 机制 | 实现位置 | 效果 |
|---|---|---|---|
| **第 1 层** | 检索无命中 → 直接拒答，**不调用模型** | `rag.answer()` 前置判断 | 杜绝"没有资料也硬编" |
| **第 2 层** | 提示词强制每个结论带 `[n]`；无编号视为无依据 | `SYSTEM_PROMPT` | 让答案自带溯源义务 |
| **第 3 层** | 服务端解析 `[n]` → 校验是否越界 → 越界标记丢弃、答案中删除并记录告警 | `sanitize_answer()` / `split_marks()` | 模型编造编号时可控降级 |

**第 3 层是实测出来的需求**：开发中出现过模型引用 `[13]`、而上下文只有 12 条片段的情况。若不做校验，前端会显示一个点不开的死链——这比拒答更伤信任。

**判定语义**：`refused = 无合法引用 且 含拒答措辞`。只有措辞不算拒答（会误伤"资料没提 X，但提到了 Y [1]"这类部分回答）。

实测结果（20 篇论文 / 4784 分块）：

| 指标 | 结果 |
|---|---|
| 官方 5 个单篇问题 | **5 / 5 通过** |
| 扩展标准问题（8 个） | **8 / 8 通过** |
| 无关问题（"今天北京天气怎么样"） | 正确拒答，引用 0 条 |
| 编造编号 | 出现后被第 3 层拦截并记录告警 |

## 4.4 检索参数标定

参数不是拍脑袋定的，每个都对应一次实测：

| 参数 | 取值 | 标定依据 |
|---|---|---|
| 片段数 `top_k` | **16** | 演进：6 条时 GPU 问题排不进 → 8 条在 8 篇论文下够用 → 库增至 15 篇（4314 块）后 12 条又不够 → 16 条可命中（当前 20 篇 / 4784 块仍取 16）；20 条不再提升，只白耗 token |
| RRF 常数 | 60 | 参考 RRF 原论文经验值；本项目未调参 |
| IDF 过滤阈值 | 相对区分度 ≥ 0.5 | 低于此值时 BM25 命中的基本是"the / of / 模型"这类高频词，进入融合反而挤掉向量结果 |
| 过滤最小语料 | 20 块 | 语料太小时 IDF 统计不可靠，直接关闭过滤 |
| 单篇配额（已锁定范围） | `max(2, ceil(top_k / 篇数))` | 多篇对比时保证每篇都有位置，避免一篇垄断 |
| 单篇配额（全库） | `max(3, top_k // 2)` | 允许主论文多占，但留位给其他论文与元信息 |

**一个重要陷阱**：片段数必须随语料规模上调。库从 8 篇扩到 15 篇后，原先"够用"的 12 条重新变得不够——**这类失效是静默的**（不报错，只是答案变差），只能靠标准问题回归测试发现。因此第 7 章把 8 个标准问题固化成了验收脚本。

## 4.5 十项优化策略

| # | 策略 | 解决的问题 |
|---|---|---|
| 1 | 标题感知分块：章节标题随块携带 | 片段脱离上下文后无法判断属于哪一节 |
| 2 | 中文 2-gram + 英文词形归一（BM25） | 中文无空格，按词切分需要词典 |
| 3 | 首页块固定注入 | 作者、机构、单位只出现在首页，语义检索不保证召回 |
| 4 | 参考文献块按需注入 | "列出某条参考文献"类问题需要 References 章节 |
| 5 | 引用编号服务端校验 | 模型编造 `[n]` |
| 6 | 拒答语义二元判定 | 只按措辞判会误伤部分回答 |
| 7 | 假拒答剥离 + 拒答重试 | 有资料却拒答 |
| 8 | 检索降级链（向量→关键词→回退） | 嵌入服务不可用时不能整体不可用 |
| 9 | 分块翻译缓存 | 整篇翻译重复调用，成本与延迟翻倍 |
| 10 | 代码/公式跳过翻译 | 误译代码会破坏可执行性 |

## 4.6 效果与成本

| 指标 | 实测值 | 测量条件 |
|---|---|---|
| 检索耗时 | 0.2 ~ 0.4 s | 4784 分块，混合检索 |
| 首字延迟 | 0.68 ~ 0.87 s | SSE 流式，含检索 |
| 完整回答 | 3 ~ 6 s | 16 条片段上下文 |
| 单次问答 token | 约 6k 输入 / 0.5k 输出 | 16 条片段 + 提示词 |
| 单次问答成本 | 约 0.01 元 | DeepSeek 定价折算 |
| 全库嵌入成本 | 约 1.7 元 | 4784 块，0.7 元/百万 token |

**成本结论**：按每天 100 次问答估算，月成本约 30 元——这是本项目敢用真实模型而非本地小模型的前提。若要求完全离线，可换本地 7B 模型，代价是中文长文问答质量明显下降。

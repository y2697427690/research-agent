第 1 章 项目概述

1.1 项目背景

科研人员读一篇论文的时间成本，远比"读不完"更具体：为了确认一句话里的数字，往往要把 30 页 PDF 从头翻到尾；用通用大模型总结论文时，模型会给出格式漂亮但出处不明的结论，逐条回原文核对的时间比直接读还长；当同一方向积累到十几篇论文时，引用关系散落在各自的参考文献里，很难判断哪篇是奠基工作、哪篇只是衍生。

本项目针对这三件事分别给出可验证的答案：

痛点 具体表现 本项目的应对
找想确认「训练 Base 模型用了多少 GPU」，需要通读全文混合检索（关键词 + 向量）定位到段落级片段
核大模型总结会编造，无法判断哪句话有原文支撑抗幻觉三层机制：无命中即拒答、强制引用编号、服务端校验编号
连十几篇论文的引用关系散落在参考文献里抽取引用关系并构图，用入度 / PageRank / 连通分量识别基石论文

1.2 项目目标

构建一个面向个人科研阅读的 AI 助手，覆盖"上传 → 解析 → 检索 → 问答 → 阅读 → 翻译 → 引用分析 → 写作"的完整链路，并且做到：

  1. 每个结论都能溯源：回答里的每个编号都能点回原文段落；
  2. 没把握就拒答：检索不到或在资料中找不到依据时，明确说"资料中没有"，而不是编造；
  3. 界面上的数字都能追到数据库：不展示无法追溯的统计，宁可移除；
  4. 工程上可验证：后端单元测试、前端冒烟测试、线上端到端验证三层覆盖。

1.3 目标用户与使用场景

面向个人研究者、研究生与高年级本科生。典型使用场景：

  • 精读单篇：上传一篇论文，反复追问方法细节、超参数、实验设置；
  • 横向对比：上传同一方向的多篇论文，让系统分述各家做法并指出承袭与差异；
  • 文献综述起步：先看引用图谱确定主干文献，再逐篇问答；
  • 非母语阅读：中英对照阅读，代码与公式保留英文原文。
